Features et thèmes

Regrouper les stories qui portent une même valeur métier, appelées Thèmes côté métier.

Une Feature regroupe des stories qui portent une même valeur métier ; elle tient lieu d’epic. Dans la vue métier, on l’appelle « Thème ».

Créer et ordonner les Features

Le Product Owner gère les Features depuis la vue technique, vue Features. Nouvelle Feature ouvre une fenêtre, où il saisit :

  • le Nom de la Feature, unique dans le projet ;
  • une Description ;
  • le Type : Fonctionnelle, ou Enabler pour un socle technique ;
  • la Valeur métier, de 0 à 100 ;
  • une Couleur, parmi douze teintes : Youm propose d’office la moins employée du projet, et les teintes déjà prises portent le nom de leur Feature, réutilisables d’un clic. Elle est reprise par toutes les stories rattachées : le nom de la Feature s’affiche dans sa couleur à côté du titre de chaque story, en liste comme dans l’affichage en tableau.

Chaque Feature reçoit un identifiant lisible, par exemple PORTAIL-F1.

La vue Features présente les Features en Cartes, par défaut, ou en Liste. Chaque carte porte la couleur de la Feature, son type, sa valeur métier, son état, le début de sa description et son avancement : une part par story, dans la couleur de son état, avec le nombre de stories validées sur le total. En pied, le nombre de stories, le total des points et les personnes qui portent leurs tâches. Youm retient la présentation choisie sur le poste.

Le Product Owner les ordonne avec les flèches Monter et Descendre de la liste, ou depuis le menu « … » d’une carte. Choisir le nom d’une Feature ouvre son panneau pour la modifier ; les autres gestes, dont Modifier et Clôturer, sont dans son menu « … ».

Le petit « i » à côté d’un champ dévoile une précision dans une bulle.

Rattacher une story

Dans le détail d’une story, côté technique, le Product Owner choisit sa Feature dans la liste, ou Aucune pour l’en retirer. Une Feature terminée ne reçoit plus de story.

État d’une Feature

L’état d’une Feature se calcule à partir de ses stories :

  • À faire tant qu’aucune n’est en réalisation ;
  • En cours dès qu’une l’est ;
  • Terminée quand toutes sont validées.

Le Product Owner peut la Clôturer à la main, depuis son menu « … », seulement si aucune de ses stories n’attend encore d’être validée. Une Feature clôturée à la main se Rouvre ; une Feature terminée parce que toutes ses stories sont validées le reste.

Regrouper les demandes par thème

Dans la vue métier, la case Regrouper par thème range les demandes sous le nom de leur Thème, puis celles Sans thème. Le regroupement est facultatif : proposer, suivre et valider se font de la même façon.

Stories techniques

L’équipe crée aussi des stories techniques depuis la vue technique, avec Nouvelle story et le type Story technique. Elles n’apparaissent pas dans la vue métier. Une demande que son auteur change en story technique, depuis la vue technique, y reste visible : elle découle d’une demande. Un invité ne crée pas de story technique.
